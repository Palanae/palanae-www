# palanae-www

The one-page brand site for `www.palanae.com`, per D1 of
[`../PALANAE-LAUNCH-PLAN.md`](../PALANAE-LAUNCH-PLAN.md): split topology, with
`app.palanae.com` serving the platform from the separate `sai-platform` project.

Next 16 · React 19 · Tailwind v4 — the same stack as the platform, deliberately, so the
token file can be copied between them without translation.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run lint       # eslint
npm run typecheck  # tsc --noEmit
```

## Where the design comes from

`app/globals.css` is a **port, not a redesign**. Every `--raw-*` value is copied verbatim from
the platform's `app/globals.css` (STR-140's ink/cloud system), including the accent decision
(moss `#3F6212` light / volt `#C8FF00` dark) and the AA corrections that came out of it
(muted text at 56% light / 50% dark, `border-strong` at 16%). When the platform's palette
changes, re-copy that block rather than hand-editing values here.

Two deliberate divergences, both documented in the file's header comment:

1. **Dark-only.** `--palette-*` is pinned to the dark ramp; there is no `prefers-color-scheme`
   block and no toggle. The light values are still carried so the port stays verifiable and so
   flipping the site is a repoint, not a colour-picking exercise.
2. **Marketing type scale.** The platform's `text-display` is 24px because it sits above data
   tables. `text-hero` / `text-headline` / `text-lede` / `text-copy` are new. Same family and
   weights (Plus Jakarta Sans 450, Geist Mono for figures) — only sizes differ.

🔴 **Hand-written CSS references `--palette-*`, never `--color-*`.** The site is single-theme
today, which makes that bug invisible; it would appear the moment a theme toggle is added,
which is exactly when nobody would think to look.

## Where the copy comes from

Every product claim on the page traces to the approved knowledge base
(`../palanae-kb/`, v1.1 2026-08-20) — chapters 1, 3, 4, 5, 8. That is the one source already
reviewed for accuracy. Three guardrails hold on this page and must keep holding:

- **No customer or prospect named**, and no anonymized stand-in specific enough to identify
  one. Naming an industry and a country together is usually already too specific.
- **No delivered-outcome claim.** Every claim is about how the software is built.
- **No counts or metrics.** The case study's verified figures (tests, RLS tables, migrations)
  are true of a repo on a date and go stale silently on a page nobody re-verifies.

Deliberately omitted: the knowledge base's "never audio, text transcripts only" commitment
(KB §8.3). The same claim was cut from our published case study as unverifiable against the
code. Reinstate only with a citation.

## Notes

- **No logo asset**, by design — text wordmark only until Class 9/42 clearance. That is also
  why there is no `opengraph-image`.
- **Ships no client JavaScript except the contact form.** Everything else is a server component.
- The header's anchor nav is hidden below `md`. On a single-scroll page that is a defensible
  trade rather than an oversight, but it does mean mobile visitors have no section jump.
- `AGENTS.md` / `CLAUDE.md` in this directory are generated by `next dev`, not hand-written.
